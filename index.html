10 · FAQ · application notesThe questions you’re about to ask.

Want the long version? How PlayGuard works walks through every mechanism and every environment variable.

AN-01Which agents does it work with?

Any MCP client that launches stdio servers: Claude Code, Claude Desktop, Cursor, Codex and others. Node.js 20.18.1+ is the only requirement; npx fetches PlayGuard on first start. Codex takes the same command, args and env as a [mcp_servers.playguard] table in ~/.codex/config.toml.

AN-02Which MCP servers can PlayGuard run?

Playwright MCP (bundled, always on), Figma — either Framelink figma-developer-mcp or Figma's official desktop server — Chrome DevTools MCP, Shopify Dev MCP and Context7. Each optional one is switched on by its own env var in the same playguard entry; leave the variable out and it never starts.

AN-03Can I use Figma MCP and Playwright MCP together?

Yes — Figma-to-code with browser checks is the work PlayGuard is built for. One playguard entry runs Playwright MCP and Figma (Framelink or the official desktop server) side by side, so the agent reads the design with the Figma tools and drives the page with browser_* over one connection. With Framelink, playguard_compare_design compares a Figma node against the live DOM element that implements it and reports mismatches numerically — font size, colour, padding, radius. Chrome DevTools, Shopify Dev and Context7 can run in the same entry too.

AN-04Is PlayGuard a replacement for Playwright MCP?

It wraps it. PlayGuard bundles @playwright/mcp and runs it as an always-on upstream, so the agent keeps the same browser_* tools — with snapshots compacted by 70–90%, dead sessions revived and the last URL restored. That is why you drop your separate Playwright MCP entry once PlayGuard is in the config.

AN-05Do I remove my other MCP entries?

Yes, for the servers PlayGuard runs. Playwright MCP is bundled and spawned by PlayGuard itself — listing it separately starts two browsers and duplicates the tool list. The same goes for a Figma, DevTools, Shopify Dev or Context7 entry you route through PlayGuard: one entry replaces all of them.

AN-06Framelink or the official Figma MCP?

Framelink works on any Figma plan with an API key and gets the full treatment: the 8-module optimizer, the cache and playguard_compare_design. The official desktop server (FIGMA_MCP_URL=http://127.0.0.1:3845/mcp) needs no key but a Dev or Full seat on a paid plan; it returns generated code, variables and screenshots, which PlayGuard passes through whole. One at a time; the URL wins if both are set.

AN-07Can I proxy Figma's remote server, mcp.figma.com?

No. Figma only admits clients listed in its MCP catalog, so PlayGuard refuses that URL at startup and says why. Add it to your MCP client directly, next to PlayGuard; its responses then skip PlayGuard.

AN-08What happens if one upstream fails?

Only its own tools go away. Optional upstreams start lazily and are isolated from each other; calling a tool of one that failed returns [PlayGuard] … MCP is not running with what to check. A crashed upstream process is respawned once and the call retried; DevTools also reopens its last URL.

AN-09Does Chrome DevTools MCP share the Playwright browser?

No — it launches its own Chrome. Pages, cookies and element ids are not shared: a DevTools uid works only with DevTools tools, a [ref=] only with browser_*. Use it for network, performance traces, Lighthouse and computed CSS; keep clicking through flows with browser_*. Advanced users can point both at one Chrome over CDP.

AN-10Can it break my agent by hiding something?

Compaction keeps every line carrying a [ref=] (or DevTools uid) plus structural landmarks, so nothing the agent can act on disappears. Static text without a ref is dropped — when the agent needs to read copy, it uses the section/around filters, browser_evaluate, or raw: true. Doc rewrites never cut content or code, and every rewrite passes an unrecognised response through unchanged. raw: true on a call, or PLAYGUARD_COMPACT=false, PLAYGUARD_DEVTOOLS_OPTIMIZE=false, PLAYGUARD_DOCS_OPTIMIZE=false, returns the untouched response.

AN-11Where do my API keys go?

Only to the upstream that needs them. Chrome DevTools, Shopify Dev and Context7 each get a filtered environment, so FIGMA_API_KEY never reaches them and CONTEXT7_API_KEY reaches Context7 only. Keys never land in the call log or the cache. PlayGuard also turns off DevTools usage statistics and CrUX lookups and Shopify Dev instrumentation by default. Its only own network request is a startup version check on npm (PLAYGUARD_UPDATE_CHECK=false turns it off).

AN-12What does the proxy cost me?

About 1–3 ms per Playwright call, measured by npm run bench. Against a snapshot that shrinks from 300 KB to 30 KB, that is not the number worth worrying about.

AN-13How do I know the savings are real?

Every call is logged as NDJSON with raw and kept byte counts and the upstream it went to — set PLAYGUARD_LOG_DIR to pick the folder. npm run analyze, run from a clone of the repo, turns your own logs into a report with savings per upstream, cache hits and latency percentiles per tool.

AN-14What about screenshots?

Your call: allow, warn (default), block, or redirect — the last swaps a screenshot for a snapshot, with {visual:true} as the escape hatch when you genuinely need pixels. The policy applies to DevTools take_screenshot too.
